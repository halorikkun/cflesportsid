# Site antislop audit

Date: 15 September 2026

## Summary

Nine findings: five HIGH, one MEDIUM, three LOW. Fix keyboard access, contrast, and touch targets first. The existing visual direction is coherent; a wholesale redesign is unnecessary.

This is an audit of the current local site, not a release approval. Only this report was added during the review. Priority follows antislop's tiers; HIGH does not mean every issue has equal user impact.

Design read: a Crossfire: Legends competition hub for Indonesian players and spectators, using charcoal surfaces, orange emphasis, game artwork, and dense statistics. Observed dials: ENERGY 3 / RHYTHM 2 / MOTION 1. These describe the existing site, not a new owner-approved design brief.

## Findings

### 1. HIGH: Some text fails contrast requirements

**Rule:** R-25. Small text must reach 4.5:1 contrast.

- On `/veto`, “Start a Scrim Veto” uses white text on `#ff742e`, measured from browser styles. Contrast is **2.70:1**. Its 16px bold text fails even the 3:1 large-text threshold.
- The shared death/loss red `#ef4444` on table background `#252528` is **4.06:1**, below the threshold for small statistics. This pairing appears in player statistics; alternating row fills also need checking.
- Source: `src/pages/veto.astro:1038`, `src/styles/global.css:15`, `src/styles/global.css:223`, `src/styles/global.css:250`.
- Fix: use the existing dark foreground on orange buttons and a lighter red for small text. Verify actual row, badge, hover, and selected backgrounds before applying a shared color change.

### 2. HIGH: Player sorting is mouse-only

**Rule:** R-32. Every interactive operation must be keyboard accessible.

- On `/players`, sortable headings are plain `<th>` elements with click listeners. The rendered headings have no button, tabindex, or interaction role. Keyboard users cannot reach and activate the sorting operation.
- The active sort has a visual arrow but no `aria-sort` announcement.
- Source: `src/pages/players/index.astro:102`, `src/pages/players/index.astro:698`.
- Fix: place a native button inside each sortable heading, preserve header semantics, and update `aria-sort` on the active column.

### 3. HIGH: Pagination removes keyboard focus after activation

**Rule:** R-32. Keyboard navigation must retain a predictable position.

- On `/maps/satellite`, activating Page 2 with Enter changed the data and current-page indicator, but `document.activeElement` became `BODY`.
- Rendering clears and rebuilds the pagination buttons. The focused button is removed without restoring focus. Players, teams, and matches use the same rebuilding pattern; those are source-confirmed candidates for the same fix.
- Source: `src/pages/maps/[id].astro:661`, `src/pages/players/index.astro:545`, `src/pages/teams/index.astro:148`, `src/pages/matches/index.astro:244`.
- Fix: preserve existing controls or restore focus to the equivalent control after rendering. Verify next/previous boundaries and numbered-page activation.

### 4. HIGH: Several mobile controls are smaller than the skill's touch minimum

**Rule:** R-03 and antislop-layoutmobile's 44 × 44px target requirement.

- At 375px width, the shared menu button measures **40 × 30px**.
- Teams/matches pagination arrows measure about **38 × 44px**; several numbered buttons on directory pages are 39–43px wide.
- Map sorting controls measure only about **27px high**, even when their table cells are taller.
- Source: `src/components/Header.astro:79`, `src/styles/global.css:275`, `src/pages/maps/[id].astro:1387`.
- Fix: give the actual buttons a minimum 44px width and height while retaining gaps. Add a visible “Menu” label for discoverability if it fits the header.
- This is the skill's target-size requirement, not a claim that every sub-44px control necessarily violates WCAG's smaller AA target-size criterion.

### 5. HIGH: Teams and matches pagination lack meaningful accessible labels

**Rule:** R-32. Navigation controls must communicate their purpose to keyboard and assistive-technology users.

- The `/teams` and `/matches` control names are only `‹`, `1`, `2`, and `›`. Their active page is represented by a CSS class without `aria-current="page"`.
- `/players` already provides “Previous page”, “Page 1”, and “Next page” labels, showing the intended behavior is available elsewhere in the project.
- Source: `src/pages/teams/index.astro:150`, `src/pages/matches/index.astro:247`.
- Fix: share a pagination convention with descriptive labels, current-page semantics, and a labelled navigation region.

### 6. MEDIUM: Homepage arrows are repeated without a distinct navigation meaning

**Rule:** R-08. Arrows should carry a specific directional meaning, not decorate most links.

- `/` uses `↗` for internal links to players, tournament results, schedules, and veto. The destinations stay inside the site, while the same glyph commonly suggests leaving it.
- Source: `src/pages/index.astro:153`, `src/pages/index.astro:223`, `src/pages/index.astro:228`, `src/pages/index.astro:242`.
- Fix: remove the repeated diagonal arrows or define one consistent internal navigation treatment. Keep pagination arrows, whose direction has a clear purpose.

### 7. LOW: The hero CTA can name the destination more directly

**Rule:** R-15. Use a specific action rather than a default “Explore” CTA.

- “Explore Tournaments” opens the tournament directory. “View tournaments” or “Tournament results” describes that destination more directly.
- Source: `src/pages/index.astro:137`.
- Fix: change only the label to match the intended directory use; retain its existing prominence and destination.

### 8. LOW: Map methodology copy interrupts reading and contains a joined sentence

**Rule:** R-20 / R-31. Information hierarchy and spacing must help readers interpret the content.

- On `/maps/satellite`, the coverage paragraph renders “did not play that map.11 of 11 map winners”. The missing space is visible in the browser.
- The same long methodology paragraph appears on empty maps, including “0 of 0 map winners”, before the empty-state content.
- Source: `src/pages/maps/[id].astro:259`.
- Fix: add explicit spacing, lead with a concise coverage statement, and put the longer calculation explanation in a labelled disclosure or separate supporting block. On empty maps, lead with the absence of recorded matches.

### 9. LOW: Duplicate styling rules make consistency fragile

**Rule:** R-31 and craftsmanship C-1. Shared visual decisions should have a clear source of truth.

- `interior.css` defines peach team cards and then replaces them with charcoal definitions later in the same file.
- Mobile menu rules are duplicated between the header component and global stylesheet. Global styling also contains historical “NEW”/“MODIFIED” comments and repeated reduced-motion rules.
- These are maintenance risks rather than a claim that the current cards are visually broken. The pagination scoping issue fixed before this audit illustrates the cost of split styling ownership.
- Source: `src/styles/interior.css:85`, `src/styles/interior.css:114`, `src/components/Header.astro:79`, `src/styles/global.css:387`.
- Fix: consolidate current shared styles, remove superseded definitions, and leave comments that explain behavior rather than edit history.

## What is working

- The dark/orange palette, game artwork, club logos, scoreboards, and competition data give the site an identifiable purpose. Dark mode is justified by this existing direction; a theme toggle is not needed merely to satisfy a generic checklist.
- The homepage combines standings, player leaders, winners, and an honest upcoming-match empty state. It is organized around useful tournament content.
- Consistent card dimensions are appropriate for comparable teams/maps; they are not automatically a violation of the card rule.
- No document-level horizontal overflow was measured on the 14 sampled routes at **320, 375, 769, and 820px**.
- Player profile tables scroll within their containers and show swipe guidance.
- No broken images were detected in the main-directory browser sweep.
- Teams/player searches and the upcoming-match filter show explicit no-results states.
- Map and match tabs switch panels. Player comparison selections display statistics and reset works.
- The mobile menu opens and closes with Escape. A shared focus-visible style and reduced-motion rules exist.
- Missing values represented by a dash in statistical tables are meaningful data placeholders, not prose punctuation defects.

### Verification blockers

- The production build completed successfully in the preceding fix on this task: 131 generated routes.
- `build:check` inspected 132 HTML files and reported one issue: it expects `sitemap.xml`, while Astro generates `sitemap-index.xml` and the robots route already points there. No missing internal file links were reported. Update the checker to match the configured sitemap output.
- All five test files and `data:check` fail to start because they import `typescript`, which is not installed/declared in the current package dependencies. This prevents a claim that statistics and veto logic passed automated tests. It is a tooling blocker, not evidence that those calculations are incorrect.
- Statistics were inspected as site data, not independently verified against external match records.

## Recommended fix order

1. Findings 1–5: contrast, keyboard sorting, focus, touch targets, and accessible pagination.
2. Finding 8: map explanation spacing and hierarchy.
3. Findings 6–7: optional copy/navigation polish.
4. Finding 9 and the verification blockers: shared-style cleanup and reliable checks.

Antislop audit mode requires approval of specific finding numbers before fixes. This report identifies the work; it does not certify the site as passing the implementation delivery gate.
