# Findings 2–5: Keyboard controls and touch targets

Completed 15 September 2026 against audit-001.

## Changes

- Finding 2: Player table headings contain native sorting buttons. The active heading exposes ascending/descending state through `aria-sort`; decorative arrows are hidden from assistive technology.
- Finding 3: Players, teams, matches, and map pagination restore focus after rebuilding. An enabled equivalent button retains focus; when Previous/Next becomes disabled, focus moves to the current numbered page. Filtering does not steal focus from the input.
- Finding 4: The shared mobile menu, directory pagination, and player/map sorting buttons have minimum 44 × 44px targets. Mobile player pagination styles now reach dynamically created buttons and permit wrapping.
- Finding 5: Team and match pagination have descriptive Previous/Next/Page labels, current-page semantics, and labelled navigation regions. Player pagination also has a labelled navigation region.

## Verification

- R-32 PASS: Enter activated all seven player sorting buttons. Text columns began ascending; numeric columns began descending. Space toggled Matches to ascending. Focus remained on the button with a solid focus outline. An ascending Kills check displayed zero-kill rows first.
- R-32 PASS: Page 2 retained focus on Page 2 for all four pagination implementations. Previous then Next at each final-page boundary moved focus to the active last-page button while Next became disabled.
- R-32 PASS: Returning to the first player page focused Page 1 and disabled Previous. An unmatched player search retained input focus and removed the pagination buttons.
- R-32 PASS: The mobile menu opened with Enter and closed with Escape, returning focus to its button.
- R-03 PASS: At 320px and 375px, players, teams, matches, and Satellite had no document-level horizontal overflow and no visible buttons smaller than 44 × 44px.
- R-35 PASS: Production build generated 131 routes. Checks ran against a fresh static preview of the built output. No browser console errors were recorded.
- Purpose/identity PASS: Existing dark/orange styles and the audit's observed ENERGY 3 / RHYTHM 2 / MOTION 1 direction remain; larger hit areas serve touch use, and native buttons serve keyboard access.

These checks cover the requested changes, not a new certification of the entire site. Existing automated-test dependency blockers from the audit were outside this scope.
